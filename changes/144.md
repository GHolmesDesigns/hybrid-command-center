### Added

- A project's tasks can now be arranged by hand. Open a project, then drag a row by the grip at
  its right-hand end, or use the position selector beside it — the keyboard alternative, which
  makes the same move and announces it. Selecting the row still opens the task, so only the grip
  carries the drag. The arrangement saves as soon as you make it and survives a reload.

### Changed

- The project page groups its tasks by workflow stage — Backlog, To Do, In Progress, Review,
  Complete, in that order, each with its own count — instead of listing them flat. Empty stages
  are not shown.
- Task lists that cross statuses now read in workflow order everywhere. They were sorted by the
  status spelling, which put Complete second and To Do last: invisible on the Status board, where
  each column holds one status, and wrong anywhere a list mixed them.
- There is one order per stage and both views read it: the arrangement made on a project page is
  the one the Status board's column shows, and a move made on the board changes what the project
  page shows. A project page hides the tasks other projects have in the same stage, and moving a
  row leaves those hidden tasks where they were. Tasks change stage on the board or from the task
  itself; the project page's groups cannot be dragged between.

### Breaking changes

None.
