## Added

- **A merge now chooses which record's details survive, field by field.** The **Merge client**
  summary lists **Name**, **Contact name**, **Email**, **Phone**, **Website**, and **Notes** with
  what each client holds beside them, and every one offers **Keep destination**, **Use source**, or
  **Custom value** with a box to type in. Until this release the client you kept always won, so a
  survivor could carry a dead phone number while the record being merged away had the current one.
- Every field starts on **Keep destination**, including one the client you keep has left blank
  while the duplicate has something in it. Which of two values is the current one is a decision
  about your own records, and a merge that quietly filled in the gaps would be making it for you.
- A typed value is checked the way the client form checks it: an email has to be an email, a
  website has to be an address, a name has to be a name. Clearing a field is deliberate — leave the
  box empty — and **Name** is the one field that cannot be cleared.
- The summary says what the client's web address becomes when you keep a different name for it.

## Changed

- **The confirmation now covers the values as well as the work.** The summary's fingerprint
  includes every value you selected and both records' current values, so changing a choice reloads
  the summary before **Merge clients** is offered again, and a merge is refused with the same
  "review the new preview" message as before if someone edited a contact detail on either client
  while the summary was on screen.
- The success message says how many fields changed beside how many projects moved.

## Notes

- The client you keep is the only record a choice writes to. The duplicate keeps everything it had,
  readable on its archived record, whichever values you took across.
- Nothing else about the surviving client is chosen here: its status, its Drive folder, and its
  Drive connection are untouched, and no Drive folder is moved, renamed, created, or deleted — as
  before. A merge still writes no integration activity row: it is local workspace surgery.
- Its web address follows the name it keeps. Keeping the destination's name leaves the address
  exactly as it was; any other surviving name rebuilds it from that name, which is what renaming a
  client has always done. Nothing in the application is addressed by it, so no link changes.
- Projects, tasks, and every other kind of record are unaffected: this chooses between two client
  records' own fields and nothing else.

## Breaking changes

None. A merge confirmed without touching a single field does exactly what it did before — the
client you keep reads the same afterwards as it did beforehand.
