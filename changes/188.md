## Changed

- The publishing preview now reports each channel separately, naming the provider account it
  resolved to and its own state — ready to send, blocked, or not available from this provider — so
  a limit is read beside the account it applies to instead of in one merged list. A caption over
  X's 280 characters no longer looks like a problem with the whole post.
- A refusal now says what has to change: how many media items to remove, what media to add, or
  which post format the platform will not take.
- Blog is reported as **Not available from this provider** rather than as a general warning, which
  is what it has always been — no provider publishes to a blog, so post it yourself and mark the
  post published.
- The preview now judges a post by what it is: a carousel, a reel, a story, and a standard post
  meet different limits. A story warns that its caption will not reach the reader before the text
  is lost, and a format a platform cannot take is refused by name.
- Media a platform does not accept is now refused rather than sent — a PDF to X, for example. Media
  whose kind cannot be read from its URL is reported as unchecked instead of assumed.

## Added

- One shared record of what each platform accepts — caption and media limits, media combinations,
  post shapes, automatic and manual finish, per-platform and per-account content overrides, first
  comments, titles and descriptions, cover images and thumbnails, synthetic-media disclosure, and
  provider drafts. Anything the app cannot answer for is refused rather than attempted, and the
  supported contract is written down in `docs/publishing-integration.md`.

## Fixed

- The API server starts again. Signal's channel colours reached the contrast helper through an
  import the server's TypeScript loader could not resolve, so the API exited at boot and the
  browser workflow suite could not run at all.

## Breaking changes

None.
