## Added

- **Figures**, below Delivery on a Signal post: what the platforms themselves counted for the post
  that went out — views, likes, comments, and shares, one set per account it was sent to. Every number
  is the provider's own; this app calculates nothing from them.
- **Daily history** where the provider keeps it, shown as what each day *added* rather than as a
  running total, so a day that gained nothing reads as nothing gained. The dates are the provider's
  own labels for its days.
- **Refresh figures** is the only thing that goes and looks. Opening a post shows the figures that
  were fetched last time and asks the provider nothing, and the panel says when the last
  synchronisation happened — or that there has not been one yet.
- One synchronisation covers every platform this provider reports figures for: TikTok, YouTube, and
  Instagram.
- A channel outside those three says **Not available from this provider** and shows no number at all.
  A zero would mean nobody watched; what is true is that nobody measured, and those are different
  claims.
- Two other honest answers instead of a number: **No delivery result to ask about**, when the provider
  has not yet said which of its results a delivery is — press **Refresh delivery** first — and **No
  figures yet**, when the platform is measured and simply has nothing for this post so far.

## Changed

- A delivery now keeps the provider's own identity for itself, captured when its delivery is refreshed.
  That identity is the only thing the provider's figures will answer a question about, so it is what
  makes any of the above possible. A later answer that omits it never erases it.

## Notes

- **A refresh that fails cannot overwrite a good figure.** Every number is read from the provider
  before anything is stored, so a refusal, an unreachable provider, or a daily history that cannot be
  read leaves the last figures exactly as they were, on screen, beside the reason.
- **A provider that asks this app to wait is waited out.** When Post Bridge rate-limits a
  synchronisation, the panel names the time it is waiting until and the button is unavailable until
  then; each refusal in a row waits a little longer than the last, up to a minute. `Retry-After` is
  honoured whenever the provider asks for longer than that.
- Figures never write a post, a schedule, a planning status, or a delivery answer. The reading path
  holds no way to publish, reschedule, or withdraw anything, and there is no timer on it — nothing is
  synchronised because a page was opened.
- Analytics needs `POST_BRIDGE_API_KEY`, the same key publishing uses. Without it the panel says so
  rather than showing an empty table.
- The provider's own API documentation disagrees with itself about which platforms it measures — one
  line says TikTok only, and the endpoint that does the work names three. `docs/publishing-integration.md`
  §16 records the disagreement and which half this app follows, and why.
