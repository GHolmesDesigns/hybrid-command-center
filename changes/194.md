## Added

- **What needs attention**, above the Signal planner: an in-app summary of what your own posts and
  deliveries say is wrong, so a problem no longer waits for somebody to go looking for it. It reports
  six things — a post that was not delivered, was only partly delivered, or whose result the provider
  never confirmed; a delivery the provider accepted that only you can finish, in Instagram, TikTok, or
  Post Bridge; a post marked **Scheduled** whose time is close or has passed with nothing submitted; a
  delivery the last provider check moved, named as the move it made; a channel with nothing planned
  inside the window; and the provider rate-limiting this app or delivery answers going stale while a
  submission is still waiting on one.
- Every line names the post it is about, and that name is a link that opens the post — including a
  post in another month, which the planner fetches rather than pretending it is not there. A post can
  now be addressed directly, so a link to one survives being bookmarked or shared.
- **Acknowledge** records that you have seen a line and takes it out of the counts. It changes nothing
  else: not the post, not its schedule, not its planning status, and nothing the provider is holding.
  If the situation then changes — a second account fails, the coverage window is widened — the line
  comes back, because it is no longer the situation that was acknowledged. **Put back on the list**
  undoes one.
- **Alert windows** sets how many hours of warning a slot gets, how far ahead a channel is expected to
  have content, and how old a provider synchronisation may be before it is called behind. Coverage can
  be limited to named channels; left empty it asks about every channel this workspace has ever used, so
  a channel you do not post to is never reported as a gap.

## Changed

- A delivery record now keeps what the last provider check concluded and what it held before that, so
  "the provider told us something new" is a fact rather than a guess. A check that finds nothing new
  clears the marker, and an action you take afterwards — a cancel, a resubmit — stops the change being
  reported, because you already know.
- A provider rate limit is now recorded as what it is: a fact about the connection rather than about
  one post. `Retry-After` is honoured where the provider sends one, reaching the provider again clears
  it, and while it is in force the summary says so instead of leaving stale delivery answers looking
  current.

## Notes

- Nothing here is emailed, texted, or pushed to a phone, and no such service was introduced. The
  summary exists in the app and is read when the planner is opened.
- Analytics remains unread by this app, as `docs/publishing-integration.md` §14 already decided. The
  synchronisation alert is about the provider data this app really does synchronise — delivery answers
  — and is written so that an analytics sync, if one is ever added, stamps the same record and needs no
  new alert.

## Breaking changes

None.
