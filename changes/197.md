## Added

- **A client can now be imported by identity rather than by name.** The `Clients` tab of a campaign
  playbook takes two optional columns — `client_import_source`, the source the playbook was written
  from, as a UUID, and `client_import_id`, the id the client has there. The first import records that
  pair against the client, and from then on it is what the client is found by. Rename the client at
  its source and the next import resolves the same client instead of creating a second one beside it,
  which is what used to happen and what quietly split a client's work across two records.
- The dry run says which rule matched, as it always has: **found by its identity**, **found by name
  with the identity about to be recorded against it**, or the ordinary name match. A playbook with
  neither column, or with the cells left blank, behaves exactly as it did before.
- The **Merge client** summary now lists every import identity that will move to the client you are
  keeping, beside the projects. A merge carries them across, one hop, so a playbook naming the
  duplicate at its own source lands on the work rather than beside it.
- The sample playbook (**Download sample playbook**, on the Import page) has both columns filled in
  for both of its clients, so it is also the worked example: import it, rename either client, and
  import it again.

## Changed

- **An identity and a name that disagree refuse the whole import.** When a row's identity belongs to
  one client and its name matches a different one, nothing at all is written — not that row and not
  the rows that would have been fine — and the check names both clients. One of the two records is
  wrong, or they are duplicates that want merging first, and neither is a choice the application
  should make for you.
- An identity is never moved from one client to another by an import. Merging clients moves it, and
  that is the only thing that does. One client can carry several identities — one per source it came
  from, and more than one from a single source once two of that source's clients have been merged
  together here.
- Recording an identity is not counted as a created record. The row created nothing; what changed is
  what the workspace knows the client by, and the check says so as the reason the row was skipped.

## Notes

- Identity is for clients only. Projects and tasks still match by name under the client or project
  they belong to.
- An existing database gains the identity table on first start and arrives with it empty: which
  client a source calls what is something only a playbook carrying that pair can say, so there is
  nothing for an upgrade to fill it from.

## Breaking changes

None. Every playbook that imported before this release imports the same way after it, and the two
new columns may be left off a workbook entirely.
